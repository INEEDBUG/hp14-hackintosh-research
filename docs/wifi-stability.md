# 原生 Wi-Fi 稳定性：实验修正

## 症状与证据

用户报告控制中心从一个路由器切换到另一个时“无法加入”，设置内关闭再开启 Wi-Fi 后可恢复；扫描显示较慢；偶尔断开后自动重连。

最近一次日志窗口混有用户主动切换和开关 Wi-Fi。苹果本地断开理由不直接等于空口管理帧原因，不能把该窗口全部算作自动掉线。随后一分钟的只读观察未复现断开，不能据此给出稳定性通过结论。

固定源码为 `laobamac/itlwm` 的 `f26a3afc8a0eecd6995ebdba48498f36bac107ad`。对当前实际驱动的窄范围离线核对也确认了对应的扫描末尾拒绝逻辑；原始二进制内容不公开。

上游 [PR #1069](https://github.com/OpenIntelWireless/itlwm/pull/1069/files) 提出了相近的扫描游标修正。这里保留该线索的归属，并针对 Sequoia WCL、现有 command gate 和节点生命周期做适配；没有把未合并 PR 当成已发布修复。

## 改动

补丁：[0001-scan-cursor-and-numeric-diagnostics.patch](../patches/wifi/0001-scan-cursor-and-numeric-diagnostics.patch)

- WCL 构建中的经典扫描请求、结果与缓存清理走现有 HAL command gate。
- 接受新扫描时重置枚举状态；显式清理缓存时先使游标失效。
- 跨回调只保存节点排序键，在门内重新遍历当前树并复制结果，避免持有已释放节点。
- 先计算有界速率数，再复制速率数组。
- 增加编译期开关 `HP14_WIFI_DIAGNOSTICS`。公开构建工具默认关闭，离线实验构建显式开启。

WCL 的关联 busy / cancel / timeout 决策未在此补丁中重写。扫描树变化时枚举不是不可变快照；排序键能避免陈旧指针，不保证返回新插入且排序更靠前的节点。完整结果一致性和实际控制中心调用路径仍需现场证据。

## 验证

测试提取修改后的实际函数，使用上游 RB-tree 头文件与最小内核边界 fixture，检查控制流、结果和释放后读取。原始 8 项测试有 5 项失败，其中两项为 AddressSanitizer 释放后使用；扩展后的 14 项全部通过。

完整 Sequoia x86_64 实验构建编译了 73 个实际源文件并链接 kext。存在大量警告，尚未完成与未修改基线的警告比较。源码级测试和链接成功不验证内核 ABI、KPI 授权、真实固件、RF 或稳定性；没有加载该产物。

后续产物审查发现初版实验构建器关闭了栈保护，因此在任何加载之前改为 `-fstack-protector-strong` 并完整重建。当前实验产物保留 stack-canary imports；与当前日用驱动的 954 个 undefined imports 精确名称集合相同，无新增或缺失。该比较减少了链接名称差异的不确定性，仍不证明 ABI、KPI 授权或运行成功。见 [导入比较证据](../evidence/wifi-imports-20261013.json)。14 项函数测试的源码未变，结果明确复用。

## 数值诊断

| stage | 含义 |
| --- | --- |
| 1 / 2 / 3 | 经典扫描请求 / 结果 / 缓存清理 |
| 10 / 11 / 12 / 13 | WCL 扫描 / 关联 / 取消 / 离开返回 |
| 15 / 16 | WCL 扫描完成 / 关联完成 |
| 20 | 驱动收到 STA_DEAUTH，detail 为驱动理由 |
| 21 / 22 / 23 | 驱动重置开始 / 就绪 / 停止 |
| 24 | 链路 down |

诊断记录序号、stage、返回值和数值状态，按 stage 限速；新诊断不输出 SSID、BSSID、密码、原始请求或指针。上游其余日志未因此变成可直接发布的数据，完整日志仍须另行脱敏。
